Tus recursos para empezar

Tienes a tu disposición las pantallas, los estilos, las imágenes y los datos iniciales de Creature Nexus. A partir de estos recursos construirás tu aplicación con Spring Boot.

¿Por dónde empezar?

Si no sabes qué desarrollar primero, consulta la Guía de desarrollo. Encontrarás diez etapas para organizar tu trabajo y comprobar tus avances.

2. Ver e integrar las maquetas

Para ver el diseño, descomprime el ZIP completo sin cambiar la estructura de carpetas. Abre templates/inicio.html con el navegador y navega entre las distintas páginas.

Las pantallas contienen nombres de cartas, resultados y formularios de ejemplo. Úsalos para comprender el recorrido de la aplicación y después sustitúyelos por información y operaciones reales.

  1. Crea tu proyecto Spring Boot.

    Configura las dependencias que necesitas para desarrollar Creature Nexus.

  2. Copia las nueve plantillas HTML.

    Colócalas en src/main/resources/templates/.

  3. Copia los estilos, las fuentes y las imágenes.

    Conserva sus subcarpetas dentro de src/main/resources/static/.

  4. Adapta las rutas públicas.

    Las maquetas usan rutas relativas para que puedas explorarlas en el navegador. En Spring Boot utilizarás rutas públicas como /css/creature-nexus.css y /img/criaturas/dragon-igneo.webp.

  5. Genera el contenido dinámico.

    Sustituye los datos de ejemplo por información del servidor mediante Thymeleaf, incluidos los listados de cartas, mazos y resultados.

Atención a las rutas

Cuando adaptes las maquetas, revisa sus enlaces y rutas para que apunten a los controladores y recursos de tu aplicación Spring Boot.

4. Reglas de cartas, mazos y partidas

Cada carta pertenece a un único elemento y tiene valores de ataque y defensa entre 1 y 10. Su coste se calcula sumando ataque + defensa.

  • 8 cartas distintas
  • 100 puntos como máximo
  • 2+ cartas de cada elemento

Qué se puede modificar

Una criatura puede pertenecer a más de un mazo, pero no repetirse dentro del mismo. Esta es una relación muchos a muchos (N:M) entre mazos y criaturas. Tendrás que modelarla con JPA para que la composición de cada mazo quede guardada en MySQL.

Los mazos predefinidos del ordenador no pueden modificarse ni eliminarse. Los mazos personales sí pueden modificarse o eliminarse si cumplen las reglas.

Una carta no se puede modificar ni eliminar si está incluida en algún mazo.

Al comenzar una partida elegirás 3, 5 o 7 rondas. El ordenador seleccionará aleatoriamente uno de sus mazos predefinidos y verás su nombre durante el combate.

Diseña tus propias reglas de enfrentamiento usando el ataque, la defensa y el elemento de las criaturas. Deberás aplicarlas de forma coherente y mostrar cómo se ha resuelto cada ronda. Al final, gana quien haya ganado más rondas. Si ambos han ganado el mismo número, la partida termina en empate.

5. Imágenes de cartas nuevas

Cuando crees una carta, podrás añadirle una imagen de forma opcional. Si dejas el campo vacío, muestra la imagen predeterminada de su elemento.

Utiliza estas tres imágenes como ilustraciones predeterminadas según el elemento de la carta. Los registros iniciales de criaturas están descritos en cartas_iniciales.csv.

Las imágenes iniciales WebP están en la carpeta de recursos. Para las imágenes nuevas que subas desde el formulario, implementa un almacenamiento persistente de archivos JPG o PNG y guarda su referencia en MySQL.

6. Lo que vas a desarrollar

Tu objetivo es convertir las maquetas y los datos de referencia en un juego web funcional. Organiza el código Java y conecta las páginas con la lógica del servidor y la base de datos.

Spring Boot

Controladores y servicios para recibir las peticiones y ejecutar las operaciones.

Thymeleaf

Adapta las maquetas a vistas dinámicas y conecta los formularios, los errores y los mensajes.

MySQL y JPA

Guarda en MySQL los tipos, las cartas, los mazos, sus relaciones y los resultados de las partidas finalizadas.

Colecciones Java

Gestiona la mano del jugador y las partidas de 3, 5 o 7 rondas con colecciones Java en el servidor.

Partidas e historial

Durante el combate elegirás cartas de una mano de tres, que se irá reponiendo con las cartas disponibles de tu mazo. El ordenador elegirá sus cartas automáticamente, sin repetir las utilizadas. En la pantalla verás el nombre del mazo rival y el resultado de cada ronda, pero no su mano.

Guarda en MySQL únicamente las partidas finalizadas, junto con el alias, los nombres de ambos mazos, el número de rondas elegido y el resultado final. Permite consultar todas las partidas o filtrar el historial por partidas de 3, 5 o 7 rondas.
